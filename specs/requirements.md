# 需求与总体架构 v2

> v1 → v2 变更：形态从「纯本地程序」改为「服务器 + 本机执行端」混合架构；首接券商定为平安证券；通知定为 Server酱；新股策略定为全部申购；引入项目治理规则（AGENTS.md）。

## 一、业务目标

- **自动申购**：可转债（沪深）+ 各市场新股（沪主板、深主板、创业板、科创板、北交所），申购日自动顶格申购。
- **中签提醒**：T+1 晚 / T+2 早自动查询中签，T+2 缴款截止 16:00 前推送提醒，避免弃购（12 个月内累计 3 次弃购限制打新 6 个月）。
- **多账户管理**：平安证券（首接）、华宝证券、中信建投，集中管理账户与权限，批量打新。

## 二、权限与资格前置条件

| 品种 | 开通条件 | 备注 |
|---|---|---|
| 可转债 | 2 年交易经验 + 开通前 20 日日均资产 ≥ 10 万（2022 新规） | **权限按券商单独开通，不可跨券商复制** |
| 沪/深主板新股 | T-2 前 20 日对应市场日均市值 ≥ 1 万元 | 市值分市场计算 |
| 创业板新股 | 20 日日均 10 万 + 24 个月经验 + C4 | 注册制权限 |
| 科创板新股 | 50 万 + 24 个月 | |
| 北交所新股 | 50 万 + 24 个月；申购全额缴款（非信用申购） | 资金规则不同，单独处理 |
| 可转债申购 | 无需市值，信用申购，中签后 T+2 缴款 | |

系统设「权限自检清单」：每个账户录入已开通权限，申购前据此过滤标的。权限状态存 `config/config.yaml`（非敏感），由用户核实后填写。

## 三、关键时间节点

- T 日 9:30–15:00：申购窗口，系统 09:35 执行。
- T+1：出配号；T+1 晚 21:00 查中签（第一次）。
- T+2 早 08:00：补查（第二次，双保险）；T+2 16:00 缴款截止。

## 四、形态：服务器 + 本机执行端（混合架构）

```
腾讯云服务器 43.139.35.190 (Ubuntu, systemd: auto-ipo)   ← 大脑
  打新日历抓取 / 定时调度 / 状态存储 / Server酱推送 / 未来 Web 管理页
                    ↑↓ HTTP（执行端主动轮询，仅外呼）
本机 Windows 执行端                                       ← 手
  easytrader + 同花顺客户端自动化 / 券商密码 DPAPI 加密存储
```

决策理由：
1. 券商对个人无官方打新 API，唯一现实路径是客户端自动化，必须 Windows GUI 环境，**无法在 Ubuntu 服务器上跑**——因此「申购执行」只能放本机。
2. 日历/调度/通知无此限制，放服务器实现 7×24 无人值守，且与 Alpha monitor 的运维模式（git 同步 + systemd）一致。
3. 券商密码只存本机执行端，服务器不接触密码，把云端泄露的资金风险降为零。
4. 执行端对服务器**只外呼**（轮询任务 + 回报结果），家里电脑无需开端口/公网 IP。

## 五、券商接入技术路线

- 平安/华宝/中信建投三家均支持同花顺 PC 客户端登录交易 → 用 easytrader「通用同花顺客户端」模式（pywinauto + xiadan.exe），一套代码覆盖三家。
- 首接平安证券（M2 验证同花顺客户端能否正常登录平安账户，这是整个方案的关键验证点）。
- 备选：miniQMT 官方量化接口（三家均非 QMT 主流券商，二期再评估）。

## 六、模块划分

| 模块 | 职责 | 位置 |
|---|---|---|
| `data_fetch/` | 打新日历抓取（东方财富/集思录），输出规范化标的列表 | 服务器 |
| `scheduler/` | 定时编排：08:30 日历 → 09:35 申购 → T+1 21:00 中签 → T+2 08:00 补查 | 服务器 |
| `execution/` | 客户端自动化：登录→申购→回报确认→截图；中签查询 | 本机 |
| `notification/` | Server酱推送：申购日报、中签提醒、异常告警 | 服务器 |
| `shared/` | 配置加载、交易日判断、日志、运行时状态 | 两端 |

账户管理：账户元数据（券商、权限、策略）存 `config/config.yaml`；密码存本机 DPAPI 加密存储。申购策略：新股/可转债全部顶格申购（用户已确认），黑名单机制预留。

## 七、合规与风险声明

- 客户端自动化属券商用户协议灰色地带，主要风险是客户端升级致脚本失效，需用户知情。
- 自用工具，不面向他人提供代操作（涉及非法经营证券业务红线）。
- 自动申购 ≠ 稳赚：注册制新股存在破发风险，系统只做执行与提醒，不做投资建议。

## 八、里程碑

- **M1 打新提醒机器人**（纯服务器，零风险）：日历抓取 + Server酱推送 + 定时调度 + systemd 部署。验证：连续 5 个交易日按时推送且内容准确。
- **M2 平安证券单账户打通**（本机）：同花顺客户端登录 → 可转债申购 → 回报确认 → 截图留痕。先 dry_run 验证流程，再人工确认后实盘一单。
- **M3 多账户 + 全调度**：华宝/中信建投接入，申购日报，服务器-执行端任务 API。
- **M4 中签闭环**：T+1 晚自动查中签 + 缴款提醒 + 对账日志。

## 九、对标与参考

- 公众号类服务（简七中签助手、中签啦）只做日历+提醒，不做代申购——印证混合架构中「服务器做提醒」的合理性。
- 开源参考：github.com/MrZilinXiao/Auto-Make-Money（可转债自动打新+Server酱）、easytrader 文档。
