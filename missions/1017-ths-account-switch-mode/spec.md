# Mission Spec

## 任务类型
架构切换、实现、审查与真实 GUI 验收

## 目标
新增“单个同花顺客户端 + 多个同花顺登录账户”模式。每个同花顺登录账户最多管理 10 个资金账户；代码支持最多 10 个同花顺登录账户，先用 2 个真实账户验证。完整链路覆盖：启动同花顺 → 切换/登录同花顺账户 → 登录资金账户 → 打开申购与查询页面 → 核验结果 → 切换下一个同花顺账户 → 退出客户端。

## 范围
- 新模式：同花顺账户切换、月度密码登录、资金账户动态发现与切换、申购/查询、任务生命周期、准确回执。
- 归档：原双客户端模式保留代码和配置，不再作为 active 模式；失败时可恢复。
- 审查修复：批量申购 allowlist、订单台账 fail-closed、账户唯一识别、敏感信息脱敏、逐账户落盘、双进程 GUI 锁。
- 不删除原双客户端代码，不自动输入资金账户密码/验证码，不绕过安全验证。

## 关键行为
1. 同花顺账户使用客户端显示名称作为唯一标识，不配置自定义 ID、别名、券商或权限。
2. 每个同花顺账户下的资金账户由 xiadan 实际列表动态识别，最多 10 个。
   资金账户下拉允许“证券名称+资金账号”无姓名文本；点击出现资金账号/密码/验证码弹窗时先关闭弹窗，再继续下一账户，最多尝试 10 户。
3. 同花顺账户切换严格按图示：点击主窗右上角关闭按钮 → 弹窗点击“切换账号” → 等待重启 → 登录界面账号下拉选择目标账户。
4. 登录界面密码已填充时只点“登录”；为空时从 DPAPI 密文填充后再登录。明文密码不得写入配置、日志、状态或推送。
5. 任务结束通过弹窗“退出”关闭，不强杀进程。
   同花顺按任务启动、完成后退出；开机联网 catch-up 过期申购不补，中签和缺失回执继续幂等补查/补发。
6. 批量申购只允许当日打新日历 allowlist 内标的；黑名单命中即跳过；未知网格行不得提交。permissions 在新模式不参与过滤。
7. 订单台账存在损坏、未知版本或写入失败时，live 申购必须 fail-closed。
8. 同一资金账户、同一申购代码、同一业务日只允许一次提交；每户结果必须即时落盘。
9. 回执必须准确区分成功、跳过、失败、不确定，标明同花顺账户和资金账户脱敏名。
   统一模板为“标题、日期、汇总、逐项明细、下一步”，覆盖登录、申购、中签三类。

## 约束
- 单个同花顺实例同一时刻只有一个 GUI 自动化任务。
- 执行测试全部 mock，不连接真实客户端；真实 GUI 验收单独执行并留截图/日志。
- 非交易时段不产生真实委托；“全流程测试”包含真实 GUI 导航、账户切换、查询和 dry-run 指令生成。
- 不修改 `AGENTS.md`、`templates/`；不输出任何密码、SendKey、完整资金账号。
- 真实密码只可通过 DPAPI 密文进入 `config/secrets.yaml`。
