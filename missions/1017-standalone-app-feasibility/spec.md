# Mission Spec 模板

## 任务类型
分析

## 目标
评估把本项目封装为 Windows 独立应用的可行性、风险和分阶段实施路径，并明确“独立应用”的可选边界。

## 范围
- 检查现有 Python 双运行时、Windows 计划任务、同花顺外部客户端、DPAPI 凭据、配置/运行时文件和 WebUI 的封装约束。
- 对比单文件、独立目录、安装包、完整桌面 GUI 四种形态。
- 输出推荐形态、风险清单、实施计划、验收与回滚方案。
- 不改业务代码、不改正式 `specs/*.md`、不打包、不注册新任务、不下单。

## 约束
- 仅本机 Windows；不能把券商密码、SendKey、完整资金账号写入 mission 或输出。
- 不宣称“完全独立”可脱离同花顺、Windows 登录会话或外部行情接口。
- 实盘能力视为最高风险；任何后续实现必须保持 `dry_run` 优先、单次提交和 F8 核验。
- 框架结论引用官方文档并记录本次查到的版本。

## 对正式 spec 的影响
当前无。用户选定封装形态后，实施前新增 `specs/packaging.md`，并同步 `specs/requirements.md`、`INDEX.md`；若新增顶层 `packaging/` 目录，需用户批准调整 AGENTS.md 根目录白名单。
